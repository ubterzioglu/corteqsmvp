# Corteqs Ana Uygulama Planı — Mikro Batch’ler

Bu plan kadro konsolunu içermez. Kadro çalışması ayrı planda tutulur:
`docs/plans/2026-09-20-kadro-konsolu-batch-plani.md`.

Her batch tek bir sonuca odaklanır. Çıkış kriteri tamamlanmadan sonraki batch’e
geçilmez.

## Faz A — Çalışma alanı ve üretim kontrolü

### Batch 0 — Çalışma alanını kaydet

- `git status` ve staged index’i kontrol et.
- Events, relocation, arama ve dokümantasyon dosyalarını ayır.
- Commitlerde yalnız açık dosya pathspec’i kullan.

**Çıkış:** İlgisiz WIP veya başka akışın migration’ı karışmıyor.

### Batch 1 — Yerel release kontrolü

- `npm run verify:release` çalıştır.
- Built asset ve muhasebe chunk’larını doğrula.

**Çıkış:** Yerel release doğrulaması yeşil.

### Batch 2 — Canlı release kontrolü

- `BASE_URL=https://corteqs.net npm run verify:release` çalıştır.
- Canlı JS/CSS ve muhasebe chunk’larının erişilebilirliğini kontrol et.

**Çıkış:** Canlı release asset’leri erişilebilir.

### Batch 3 — Canlı güvenlik başlıkları

- `curl -I https://corteqs.net/` çalıştır.
- CSP, HSTS, X-Frame-Options, Referrer-Policy ve nosniff başlıklarını kontrol et.
- Tarayıcı konsolunda CSP ihlali olmadığını doğrula.

**Çıkış:** Nginx başlıkları ve CSP temiz.

## Faz B — Etkinlik modülü

### Batch 4 — Etkinlik deploy önkoşulu

- Events commit ve migration durumunu kontrol et.
- Coolify’ın doğru `main` commit’ini build edeceğini doğrula.

**Çıkış:** Deploy edilecek commit ve migration durumu net.

### Batch 5 — Etkinlik üretim deploy’u

- Coolify deploy’u başlat.
- Deploy loglarında build ve nginx başlangıcını kontrol et.

**Çıkış:** Events kodu üretimde yayınlandı.

### Batch 6 — Etkinlik oluşturma QA’sı

- `/events` formunu aç.
- Saat girip timezone seçmeden gönderimi dene.
- Saat girmeden gönderimi dene.
- Online etkinlikte timezone alanını kontrol et.
- Berlin tarayıcısında varsayılan timezone seçimini doğrula.

**Çıkış:** Formun timezone sözleşmesi doğru çalışıyor.

### Batch 7 — Etkinlik detay QA’sı

- `/events/:id` saat satırını kontrol et.
- Farklı timezone’da “Senin saatinle” satırını doğrula.
- Gün kayması olan etkinlikte gün adını kontrol et.
- Onay bekleyen etkinlikte paylaşım kilidini doğrula.

**Çıkış:** Yerel saat ve onay durumu doğru gösteriliyor.

### Batch 8 — Etkinlik listesi ve profil QA’sı

- Liste kartındaki paylaşım menüsünü test et.
- Kart timezone etiketini kontrol et.
- Virgüllü arama çalıştır.
- Normal üye ve premium pilot profillerinde “Etkinliklerim” panelini test et.

**Çıkış:** Liste ve profil regresyonları yok.

### Batch 9 — Etkinlik admin QA’sı

- `/admin/events` tarihlerini kontrol et.
- Durum rozetlerini doğrula.
- UTC kaynaklı gün kayması olmadığını test et.

**Çıkış:** Admin etkinlik ekranı doğru günü ve durumu gösteriyor.

## Faz C — Relocation

### Batch 10 — Relocation rota smoke testi

- `/relocation` aç.
- Header bağlantısını kontrol et.
- Plan oluştur ve URL’de `?move=` oluştuğunu doğrula.

**Çıkış:** Relocation ana akışı açılıyor ve plan URL’ye bağlanıyor.

### Batch 11 — Relocation devamlılık testi

- Oluşturulan planla sayfayı yenile.
- Planın kaybolmadığını doğrula.
- Çoklu plan arasında geçiş yap.

**Çıkış:** Sayfa yenileme ve plan devamlılığı çalışıyor.

### Batch 12 — Relocation asistan testi

- Asistan sekmesinde soru sor.
- Yanıtın geldiğini ve hata durumunun kontrollü gösterildiğini doğrula.
- Tarayıcı konsolunu kontrol et.

**Çıkış:** Relocation edge function ve frontend bağlantısı çalışıyor.

### Batch 13 — Relocation seed provası

- `docs/operations/2026-09-20-relocation-icerik-seed-sablonu.sql` dosyasını doldur.
- UTF-8 kodlamayı kontrol et.
- `BEGIN ... ROLLBACK` provası yap.

**Çıkış:** Seed SQL’i gerçek çalıştırma için doğrulanmış.

### Batch 14 — Relocation seed uygulaması

- Seed’i canlı veritabanına uygula.
- Dört tablonun satır sayılarını doğrula.
- Maliyet ve belge sekmelerini tarayıcıda kontrol et.

**Çıkış:** Relocation içerikleri gerçek verilerle görünür.

### Batch 15 — Relocation eksik sekme kararı

- İşletmeler, Okullar ve Hoşgeldin Paketi için veri kaynağını belirle.
- Mock veri ekleme.
- Veri kaynağı yoksa sekmeleri kapsam dışında bırak.

**Çıkış:** Eksik sekmeler için karar kaydı var.

## Faz D — Public rotalar ve sitemap

### Batch 16 — Public rota smoke testi

Şu rotaları tek tek aç:

- `/city-ambassadors`
- `/consultants`
- `/businesses`
- `/isletme/:slug`

**Çıkış:** Dört rota açılıyor ve temel layout bozulmuyor.

### Batch 17 — Demo içerik kontrolü

- `/businesses` üzerindeki kapatılamaz DEMO bandını kontrol et.
- Ana sayfadaki İşletmeler kartındaki DEMO rozetini kontrol et.
- `demo-pages.ts` ve `App.tsx` path eşleşmesini doğrula.

**Çıkış:** Demo işaretleri görünür ve doğru rotaya bağlı.

### Batch 18 — Sitemap ve kırık bağlantı

- `npm run generate:sitemap` çalıştır.
- Yeni public rotaların sitemap durumunu kontrol et.
- Demo işletme rotasının sitemap dışında kaldığını doğrula.
- `/radio/:id/song-request` düğmesini düzelt veya kaldır.

**Çıkış:** Sitemap ve public bağlantılar tutarlı.

## Faz E — Dizin ve arama

### Batch 19 — Anonim dizin erişimi

- `search_directory_catalog` RPC’sini anonim erişime uygun hale getir.
- Sonuçları sayfala ve PII döndürme.
- `is_directory_visible` ve yönetici elemesini koru.

**Çıkış:** Anonim kullanıcı sınırlı ve güvenli dizin sonuçları alabiliyor.

### Batch 20 — Dizin sitemap ve ana sayfa bağlantısı

- `/directory` rotasını sitemap’te tut.
- Ana sayfadaki İnsanlar kartını `/directory` akışıyla test et.
- Giriş sonrası `next` parametresinin korunduğunu doğrula.

**Çıkış:** Sitemap, ana sayfa ve anonim dizin davranışı aynı sözleşmeyi kullanıyor.

### Batch 21 — Arama normalizasyonu

- Aramayı `catalog_search_documents` üzerine taşı.
- `lower(unaccent(...))` ile Türkçe normalizasyonu uygula.
- Tam eşleşmeleri kısmi eşleşmelerin üstünde sırala.

**Çıkış:** Türkçe karakter ve ek kaynaklı boş sonuçlar azalıyor.

### Batch 22 — Arama güvenlik regresyonu

- B20 yönetici elemesini koruyan test ekle.
- Sayaç ve sonuç sorgusunda aynı filtreleri kullan.
- Anonim sonuçlarda iletişim/PII sızıntısı testi yap.

**Çıkış:** Arama güvenlik koşulları ve sayaç tutarlılığı testte kilitli.

### Batch 23 — Katalog veri kalitesi

- Bekleyen 61 uzman kaydını admin ekranında değerlendir.
- Uygun kayıtları yayına al.
- Şehir ve kategori boşluklarını azalt.

**Çıkış:** Arama yalnız teknik olarak değil, veri açısından da anlamlı.

### Batch 24 — Arama kapsamı

- Blog, etkinlik, rehber, Cadde, anket, şehir elçisi, işletme, konsolosluk ve `/tools` kaynaklarını katalog akışına al.
- `/landingtrial` üzerindeki verisiz İş İlanları çipini kaldır veya veri kaynağına bağla.

**Çıkış:** Site araması katalog profilleriyle sınırlı değil.

## Faz F — Site geneli AI bot

### Batch 25 — Embedding hazırlığı

- Katalog, 418 doküman ve 50 blog içeriğini embedding kuyruğuna al.
- İşlemi idempotent yap.
- Başarısız kayıtları raporla.

**Çıkış:** Embedding üretimi tekrarlanabilir ve izlenebilir.

### Batch 26 — Embedding üretimi

- `catalog_search_documents.embedding` alanını doldur.
- Örnek semantik sorgularla sonuçları doğrula.

**Çıkış:** Semantik arama için kullanılabilir embedding verisi var.

### Batch 27 — AI bot backend genellemesi

- `relocation-assistant` fonksiyonunu site geneli bağlam destekleyecek şekilde genelle.
- Origin allowlist, rate limit, gövde limiti ve PII korumasını koru.
- Çok turlu geçmiş ve sistem prompt desteğini ekle.

**Çıkış:** Yeni backend katalog/doküman bağlamı ile konuşma sürdürebiliyor.

### Batch 28 — ChatBot bağlantısı

- `ChatBot.tsx` bağlantısını `rag.corteqs.net` yerine yeni backend’e taşı.
- Hata ve timeout durumlarını kontrollü göster.
- `/api/chat` içindeki hatalı `hasContext: true` davranışını düzelt.

**Çıkış:** ChatBot doğru backend’i kullanıyor ve fallback gerçekten çalışıyor.

### Batch 29 — AI kalite ve maliyet kontrolü

- Gemini billing ve kota durumunu doğrula.
- Türkçe vize, denklik ve taşınma sorularıyla kalite testi yap.
- Kullanım, sağlayıcı ve hata loglarını kontrol et.
- Groq geçişini ancak kalite ölçümünden sonra değerlendir.

**Çıkış:** Bot kalitesi, kotası ve maliyeti ölçülebilir.

## Faz G — Teknik borç ve dokümantasyon

### Batch 30 — Etkinlik teknik borçları

- `events.type` ve `events.status` CHECK kısıtlarını ekle.
- Eksik timezone seçeneklerini tamamla.
- DST ve ters saat girişleri için kullanıcı uyarılarını değerlendir.

**Çıkış:** Etkinlikte bilinen veri ve saat riskleri karara bağlandı.

### Batch 31 — Relocation teknik borçları

- Rate-limit TOCTOU riskini değerlendir.
- RLS fazlalıklarını temizle veya gerekçelendir.
- `updated_at` trigger ihtiyacını karara bağla.

**Çıkış:** Relocation risklerinin her biri düzeltildi veya kayıtlı karara bağlandı.

### Batch 32 — Dokümantasyon senkronu

- `CLAUDE.md` migration/test sayılarını güncelle.
- Canlı ve repo edge function listelerini eşitle.
- Supabase çıkış dokümanlarını çıkış tamamlandıktan sonra taşı.

**Çıkış:** Dokümantasyon canlı sistemle uyumlu.

### Batch 33 — Depo hijyeni

- `walast.txt` ve `.secretdb` dosyalarını depo dışına al.
- `docs/reference-clones` ve `docs/reference` kullanımını ölç.
- `platform-safety-core.md` için arşiv/aktif plan kararı ver.

**Çıkış:** Hassas ve bayat dokümanlar için güvenli karar alınmış.

### Batch 34 — Cadde karakterizasyonu

- Cadde API ve sayfasına karakterizasyon testleri ekle.
- Testler yeşil kaldıktan sonra parçalı refactor yap.
- AuthProvider’daki savunulabilir doğrudan çağrıları belgeleyerek B6’yı kapat.

**Çıkış:** Cadde refactor’u davranış testleriyle korunuyor.

## Faz H — Final doğrulama ve teslim

### Batch 35 — Proje doğrulama

```powershell
npm run test
npm run lint
npx tsc -p tsconfig.app.json --noEmit
npm run verify:text
npm run ingest:tools:check
npm run check:migrations
```

**Çıkış:** Tüm proje doğrulamaları yeşil.

### Batch 36 — Kritik tarayıcı akışları

- Etkinlik, relocation, public rota, dizin ve ChatBot akışlarını Playwright/manual QA ile test et.
- Tarayıcı konsolunda CSP ve runtime hatası olmadığını kontrol et.

**Çıkış:** Kritik kullanıcı akışları gerçek tarayıcıda çalışıyor.

### Batch 37 — Commit ve push

- Her değişiklik grubunu açık pathspec ile stage et.
- `git diff --cached --name-status` ile index’i kontrol et.
- Conventional commit oluştur.
- Kullanıcı onayıyla `main` branch’ine push et.

**Çıkış:** Değişiklikler izlenebilir commitlerle remote’a taşındı.

### Batch 38 — Coolify sonrası doğrulama

- Deploy tamamlandıktan sonra `verify:release` çalıştır.
- HTTP header ve CSP kontrollerini tekrarla.
- Son smoke test sonuçlarını plan dosyasına işle.

**Final çıkış kriteri:** Kritik özellikler üretimde doğrulanmış, kod/test/migration/dokümantasyon kontrolleri yeşil.
